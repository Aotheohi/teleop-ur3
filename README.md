# UR3 Teleoperation — ROS 2, Feetech & Haptic Feedback

ROS 2 research prototype for teleoperating a **Universal Robots UR3** using a six-joint **Feetech master arm**, with experimental collision-response/binary haptic feedback and MuJoCo simulation.

> **Safety:** This is research software, not safety-certified robot control. Test with a clear robot workspace, low speeds, verified joint mapping and an accessible emergency stop. The master locking and collision detection logic must not replace UR safety features.

## What is included

- **Physical UR3 teleoperation:** `feetech_publisher.py` reads the Feetech master and publishes joint states. `ur3_subscriber.py` uses Universal Robots RTDE to command the UR3 and implements experimental kinematic collision detection and a binary haptic signal.
- **MuJoCo teleoperation:** `feetech_publisher_sim.py` connects the *physical* Feetech master to a simulated UR3e follower, `mujoco_subscriber_sim.py`.
- **Vision-based simulation:** `mujoco_sim_node.py` publishes virtual color/depth images, `cv_detection_node.py` detects a red object with OpenCV, and `vision_motion_node.py` generates Cartesian and gripper commands.
- **Experiments:** `matrix_5x5_mujoco.py` performs a multi-point trajectory experiment; `plot_trajectory.py` and `latency_data_stable.csv` support trajectory analysis.

The ROS 2 `build/`, `install/`, and `log/` directories are regenerated by `colcon` and should not be versioned. Python `__pycache__` and `*.pyc` files are also excluded.

## Requirements

- Ubuntu with **ROS 2 Humble** (the repository's generated files indicate a Python 3.10 environment).
- ROS 2 Python packages including `rclpy`, `sensor_msgs`, `geometry_msgs`, `std_msgs`, `ament_index_python`, and `cv_bridge`.
- Python libraries used by different nodes: `numpy`, `mujoco`, `opencv-python` (`cv2`).
- For real UR3: `ur_rtde` Python interfaces (`rtde_control`, `rtde_receive`), an accessible UR controller, and the correct network configuration.
- For Feetech input: a compatible six-servo master and USB serial interface.

**Note:** Not all runtime dependencies are currently declared in `package.xml`. Install the packages required for the specific experiment in your ROS-compatible environment.

## Build

From the repository root:

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

Source the ROS and workspace environments in **each new terminal** before running a node.

## Run physical UR3 teleoperation

Verify the UR IP address in `src/my_ur_teleop/my_ur_teleop/ur3_subscriber.py` (currently set to `192.168.1.1`) and Feetech serial port (currently `/dev/ttyUSB0`) before starting. Check servo IDs, master-to-robot joint mapping, sign conventions and safe robot speed limits.

Terminal 1:

```bash
ros2 run my_ur_teleop ur3_teleop
```

Terminal 2:

```bash
ros2 run my_ur_teleop feetech_ctrl
```

The master publishes `/master/joint_states` (`sensor_msgs/JointState`). The follower publishes `/follower/tcp_force` (`geometry_msgs/WrenchStamped`). **In the current physical-robot code, the X component of this published message is a binary collision indicator (0 or 100), not a calibrated force measurement.**

## Run Feetech–MuJoCo teleoperation

Terminal 1:

```bash
ros2 run my_ur_teleop ur3_teleop_sim
```

Terminal 2:

```bash
ros2 run my_ur_teleop feetech_mujoco
```

Despite the name, `feetech_mujoco` currently opens a **real Feetech USB device**; it is not a software-only fake master.

## Run vision-based MuJoCo demo

In separate sourced terminals:

```bash
ros2 run my_ur_teleop mujoco_sim
ros2 run my_ur_teleop cv_detection_node
ros2 run my_ur_teleop vision_motion_node
```

These components publish virtual RGB/depth frames, detect a red target, and produce motion and gripper commands. This is an experimental pipeline, not a validated autonomous grasping controller.

For the trajectory demo:

```bash
ros2 run my_ur_teleop calib_matrix
```

## Limitations and attribution

- UR3 physical control and UR3e simulation models differ; their geometry/limits are not interchangeable by default.
- The control source contains hard-coded communication settings, gains and collision thresholds. Review them before using hardware.
- Experimental CSVs and images have been deliberately retained as research artifacts.
- The repository's `setup.py` and `package.xml` still contain placeholder license metadata. The included UR3e model has a separate `LICENSE.txt` that must be respected.
- This cleanup does **not** imply that the nodes were tested on real hardware or in an end-to-end simulation.
